# jtasks for Claude Code

The Claude Code mod of [jtasks](../README.md): the `jtasks` tool (`mcp__jtasks__jtasks`, the same contract as
the CLI), the run bound to the session (`$.state`, shared by subagents), the execution protocol in the system
prompt while a run is bound, a "Tasks" pane with the checklist and `/jtasks` (Claude Code has its own `/tasks`), the model of each subagent from its
task's profile, and the ownership guard on `Edit`/`Write`/`NotebookEdit`/`Bash` of subagents.

The folder is self-contained: `core/core.js` is the core (generated from `../src` by `bun scripts/build.ts`), and
the hooks module runs it with no Node and no `node_modules`. It needs `jlock` in `PATH` and `git`.

## Install

In Claude Code, one line installs the mod from this repository's marketplace (Claude Code 2.1.275 or later):

```
/plugin install jtasks --marketplace rodrigojager/jtasks
```

Or, for one session from a clone, without installing anything:

```
claude --plugin-dir <jtasks>/claude
```

## Language

The pane, `/jtasks` and the tool's answers speak the language picked when the session starts: `JTASKS_LANG`,
then `JLOCK_LANG`, then the system's language, then English (`en` and `pt-BR` today). A single call can ask for
another with `--lang <tag>` (`{ "command": "status --lang en" }`). The tool's description and the protocol in the
system prompt are English, for the model; `--json` data is the same in every language. Set the variable before
starting Claude Code, for example `JTASKS_LANG=en claude --plugin-dir D:/jtasks/claude`.

## Tasks pane

The Tasks pane shows the bound run's progress in a claude-hud-style bar, then one row per task. For example:

```text
▾ Tasks · pane-redesign-261024-hjr6
██████░░░░ 60% · 3/5

✓ T1 - Base
✻ T2 - Pane model
○ T3 - Pane documentation
```

The bar has ten cells in claude-hud's Usage blue, the empty ones in the same blue, dim; the percentage and the
`done/total` count follow it. A green `✓` marks a completed task, its label in the normal text color. Claude Code's
orange spinner (`✻ ✶ ✽ ✢ ·`, shown here as `✻`) marks a running task, its label orange too. Upcoming tasks are a dim
`○`. A failed task has a red `✗`; a skipped one a dim `✓` with its label struck through. Use the header button to fold
or unfold the pane, or toggle it with `/jtasks`.

## Agents

The mod ships three subagents, `jtasks:execute`, `jtasks:execute-deep` and `jtasks:review` (`agents/`, generated by
`bun scripts/build.ts` from the OpenCode ones, the same text). They are saved with the mod: nothing to install. When
the model opens a subagent for a task (`--task <id>` in its prompt), the task's profile turns the call into its
agent (`claude.agent`), on its model, with its role; a profile that names no agent keeps the type the call asked for.
The profile's effort (`low`, `medium`, `high`, `xhigh` or `max`) is set on every model request of that subagent,
where the model takes one. The defaults: `execute` on sonnet, effort `medium`; `execute-deep` on opus, `high`;
`review` on sonnet, `high`.

## Check it

```
claude plugin validate claude          # manifest, hooks module, state contract
claude plugin test claude              # the tests in claude/tests (a fake machine: no git, jlock or model calls)
bunx tsc -p tsconfig.claude.json       # types, against vendor/claude-code.d.ts (Claude Code 2.1.310)
```

## The tool

```
tasks { "command": "next" }
tasks { "command": "start T04" }
tasks { "command": "claim T04 src/x.ts --timeout 2m" }
tasks { "command": "done T04 --evidence \"bun test: 12 passed\"" }
tasks { "command": "plan --add", "json": [ { "id": "T05", "title": "…", "files": ["src/y.ts"] } ] }
```

`help` lists every action. A session bound to a run refuses `--run` naming another one.
